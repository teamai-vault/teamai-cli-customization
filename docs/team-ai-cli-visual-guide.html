Team AI CLI · Quick Visual Guide

先设置“我是谁”
再告诉每个 Repo“它是谁”

不用记很多概念。先记住 3 个命令：init、projects set、sync。

init = 我·projects set = 这个 Repo·sync = 更新到最新
USER SCOPE

👤 你的机器 / 账号

Marketplace、Role、用户级 Instructions、CLI 自带 Skill。

CURRENT REPO

📁 当前 Physical Project

它绑定哪些 Logical Project，以及对应的业务 Context / Docs / Learnings。

第一次使用：3 步就够

01

初始化你自己

User Scope

team-ai init --marketplace <source> --role api
→
02

进入业务 Repo

Physical Project

cd payment-service
→
03

绑定业务上下文

Logical Project

team-ai projects set payments
注意： `projects set` 会立即把当前 Repo 的 Logical Project context 收敛好，不需要为了绑定再跑一次 `init`。

🔄 `sync` 到底做什么？

USER SCOPE

更新你的 Team AI 环境

  • 刷新 Marketplace
  • 更新 Plugins
  • 更新 User Instructions
  • 更新已安装的 managed Skills
  • 更新 built-in `team-ai` Skill
team-ai
sync
CURRENT REPO

更新当前 Repo 的业务上下文

  • 读取已保存的 Logical Project IDs
  • 更新 Logical Project Instructions
  • 更新 Docs / Learnings
  • 更新 optional Project Plugin
只更新当前所在 Repo，不会扫全机器所有 Repo。

两个最常见的 `sync` 场景

SCENARIO A

团队更新了 Payments 文档

cd payment-service

team-ai sync

# payments docs / instructions
# 自动更新到当前 repo
SCENARIO B

某个已安装 Skill 更新了

team-ai sync

# Standalone managed Skill → 更新
# Plugin-contained Skill → 随 Plugin 更新

常用命令，一眼就懂

SETUP

`init`

第一次设置 Marketplace + Role，建立你的 Team AI 用户环境。

team-ai init --marketplace ... --role api
REPO

`projects list`

看看团队有哪些 Logical Project。

team-ai projects list
REPO

`projects set`

绑定当前 Repo。一个 Repo 可绑定多个 Logical Project。

team-ai projects set payments risk
REFRESH

`sync`

刷新 Marketplace，并更新用户能力和当前 Repo 已绑定的业务上下文。

team-ai sync
ROLE

`role list / set`

查看或切换你的团队 Role。

team-ai role set qa
CHECK

`status`

快速查看 Team AI 当前状态。

team-ai status
FIX

`doctor`

状态不对？检查 missing、stale、collision 等问题。

team-ai doctor
SKILL

`skill list`

浏览团队 Skill；可按 Tag、Owner、Source 筛选。

team-ai skill list --tag experimental
SKILL

`skill show`

查看一个 Skill 是做什么的、来自哪里、是否可独立安装。

team-ai skill show release-helper
SKILL

`skill install`

安装一个或多个可独立使用的 Team Skill。

team-ai skill install release-helper
SKILL

`skill remove`

移除 Team AI 管理的 personal Skill。

team-ai skill remove release-helper
TAGS

`tags list`

看看团队当前有哪些 Skill 标签。

team-ai tags list
SHARE

`learning share`

把排障经验 / 团队经验通过贡献流程分享出去。

team-ai learning share note.md

STANDALONE SKILL

📦 可以独立安装

Standalone Skill 是可以单独放进你的个人 Copilot Skills 目录里使用的 Skill。

team-ai skill list --source standalone

team-ai skill show release-helper

team-ai skill install release-helper

# 以后团队更新了它
team-ai sync

# 不想用了
team-ai skill remove release-helper
PLUGIN-CONTAINED SKILL

🧱 通常随 Plugin 使用

有些 Skill 属于某个 Plugin。Plugin 启用时，Skill 直接随 Plugin 提供，不需要再复制一份。

# 先看它来自哪里
team-ai skill show java-review

# Plugin 已启用
# → Skill 直接由 Plugin 提供

# 如果它明确允许 standalone
# 且 Plugin 当前未启用
team-ai skill install java-review
`skill show` 很重要：不知道某个 Skill 能不能单独装？先 `show`。它会帮助你看懂 Skill 的来源、Owner、Tag、是否 Standalone，以及当前状态。

🔎 `skill list`：像浏览一个团队能力目录

看看全部

team-ai skill list

适合第一次使用，先知道团队到底提供了什么。

只看 Standalone

team-ai skill list --source standalone

想找“可以直接装到自己环境里”的 Skill 时最有用。

按 Tag 找

team-ai skill list --tag experimental

想找某一类能力，例如 experimental、java、release。

按 Owner 找

team-ai skill list --owner api-team

想看某个团队负责维护哪些 Skill。

🏷️ Tag：分类和批量选择，不是订阅

Tag = 现在帮我筛选 ≠ 以后自动跟踪
01

看看有哪些 Tag

team-ai tags list
→
02

用 Tag 找 Skill

team-ai skill list --tag experimental
→
03

按 Tag 批量安装

team-ai skill install --tag experimental
TODAY

今天 experimental 有 A / B / C

team-ai skill install --tag experimental

# 实际记录的是：
A
B
C
LATER

后来新增 D

# D 也有 experimental tag

team-ai sync

# 不会自动安装 D
为什么？ Tag 是“一次性选择器”。安装时 Team AI 会把当时匹配的 Skill 名称保存成明确的 desired state。以后要把新加入这个 Tag 的 Skill 也装进来，再执行一次 `skill install --tag ...`。
USER

我能怎么用 Tag？

列出 Tag、筛选 Skill、按 Tag 批量选择安装。

TEAM MAINTAINER

谁维护 Tag？

Tag 属于团队 Marketplace 的 Skill metadata，由团队维护者统一维护。普通用户不需要手工改 metadata。

🪪 `skill show`：安装前先看身份证

WHAT

它是干什么的？

先看 Skill description，确认它解决的问题是不是你现在需要的。

WHERE

它从哪里来？

Standalone，还是某个 Plugin 里的 Skill？

WHO

谁负责？

看 Owner，知道维护责任在哪里。

HOW

能不能单独装？

看 standalone 状态；Plugin-contained Skill 是否能独立安装，由 Team AI metadata 决定。

team-ai skill show release-helper

# 看清楚再决定：
team-ai skill install release-helper

3 个最重要的使用边界

📌 `init` = 用户设置配置 Marketplace、Role 和用户级能力。
📁 `projects set` = Repo 设置告诉 Team AI 当前 Repo 属于哪些 Logical Project。
🔄 `sync` = 更新刷新团队能力，并更新当前 Repo 已绑定的上下文。

一个完整例子

DAY 1
# 只做一次：设置用户环境
team-ai init --marketplace company/teamai-marketplace --role api

# 进入支付服务
cd payment-service

# 看有哪些业务上下文
team-ai projects list

# 当前 repo 属于 Payments
team-ai projects set payments
DAY 30
# 团队更新了 payments docs / learning / plugin / skills
cd payment-service
team-ai sync

# 想知道现在状态
team-ai status

# 感觉哪里不对
team-ai doctor
